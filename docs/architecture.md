# 云渡 Cloudrift architecture

User requirements: replicate FlClash v0.9.1 functionality and interfaces in dclash-flutter, Flutter + GetX, Termax directory conventions, reusable UI components, improve lifecycle and performance while migrating. Existing FlClash and Termax are read-only references.

`lib/app/pages/<feature>/<feature>_{view,controller,binding}.dart` owns presentation; `app/widgets` owns stateless reusable surfaces. `services` owns reactive application operations; `repositories` and `storage` own persistence; `domains` holds immutable models; `platform` isolates native integration; `configs` owns initialization, translation and themes. Riverpod is not part of this application.

Composition root: `AppInitializer.init()` assembles the long-lived services into `AppServices`. The production entry point passes that object through `CloudriftApp` and `WorkspaceBinding`, so feature controllers receive their dependencies explicitly. Individual GetX registrations remain as a compatibility bridge for legacy routes and tests; new feature code should depend on `AppServices` or a smaller module port and should not add another `Get.find<T>()` lookup.

The core module ports live in `services/core_ports.dart`: `CoreActivityPort` serves connections, request/DNS feeds and logs; `CoreLifecyclePort` exposes only start/stop/reload controls; `CoreProfilePort` adds profile and settings access for profile actions; and `CoreProxyPort` exposes runtime groups and proxy tests. Controllers use the narrowest port that supports their work. `AppServices` is narrowed further into feature-local dependency objects for dashboard, tools, settings, profiles and proxies. Shared service contracts:

* SettingsService in services/settings_service.dart: `fields` is RxMap<String,dynamic>; `Future<void> initialize()`, `Future<void> set(String key, dynamic value)`, `Map<String,dynamic> export()`, `Future<void> restore(Map<String,dynamic>)`. Keys: mode(rule), mixedPort(7890), systemProxy(false), tunEnabled(false), allowLan(false), ipv6(false), logLevel(info), stack(mixed), themeMode(system), locale(zh_CN), accent(blue), dnsOverride(''), tunOverride(''), snifferOverride(''), ntpOverride(''), addedRules(''), hosts(''), controllerEnabled(false), proxySort(default), hideUnavailable(false), autoStart(true), launchAtLogin(false), minimizeToTray(true), webdavUrl(''), webdavUser(''), bypassDomains(['localhost','*.local','127.*','10.*','192.168.*']). `autoStart` controls whether the first frame requests a connection when an active profile exists; preview builds always keep it disabled. Setters persist before publishing values. Secrets use platform secure storage.
* ProfileService in services/profile_service.dart: RxList<ClashProfile> profiles; RxnString activeId; RxSet<String> updating; RxnString error; `ClashProfile? get active`; `Future<void> initialize()`, `Future<ClashProfile> importUrl(String url, {String? name})`, `Future<ClashProfile?> importFile()`, `Future<ClashProfile> saveContent({String? id, required String name, required String content})`, `Future<String> readContent(ClashProfile profile)`, `Future<void> activate(String id)`, `Future<void> refresh(String id)`, `Future<void> remove(String id)`, `Future<void> update(ClashProfile profile)`, `Future<ClashProfile> duplicate(String id)`. Methods throw user-displayable Exceptions; never swallow failures. ConfigBuilder.build(content, fields, {script}) returns Future<String> of effective YAML. It may use QuickJS. BackupService exports/imports validated ZIPs and WebDAV.
* CoreService in services/core_service.dart: constructor `CoreService(ProfileService profiles, SettingsService settings, {bool preview = false})`; Rx<CoreStatus> status, RxnString error, RxList<ProxyGroup> groups, RxList<ClashConnection> connections, RxList<CoreLog> logs, RxList<Map<String,dynamic>> requests,dnsQueries,providers; RxInt upload,download,totalUpload,totalDownload,memory; Rxn<DateTime> startedAt; RxString version; RxMap<String,int> delays. bool get running. `Future<void> initialize()`, start(), stop(), toggle(), reload(), setMode(String), selectProxy(String group,String name), testAll(), closeAll(), closeConnection(String id), updateProvider(String name), updateGeo(String name); `Future<int?> testDelay(String name)`; `Future<dynamic> invoke(String method,[dynamic arguments])`; `Future<void> disposeRuntime()`. Only core service owns lifecycle. Reconcile latest desired intent, bounded events and process-owned teardown. Do not change host network until explicit start or user setting while running. Read-only preview is explicit `DC_PREVIEW=true`, no native networking changes.

Target runtime: Android native VpnService + gomobile and desktop Go process + local IPC, retaining upstream Go/native implementation with attribution. All ports and application identities must be Cloudrift-specific to avoid collision. Privileged platform operations retain OS authorization prompts. No promises of iOS support: reference has no iOS implementation.

UI: adaptive desktop sidebar and mobile bottom dock; dashboard status/traffic charts/mode/system proxy/TUN/profile/groups; proxies selector, filter, sort and delay tests; profiles URL/file/custom import, refresh/edit/duplicate/export/remove, script; connections, request and DNS tables; tools and settings DNS/TUN/sniffer/NTP/rules/providers/logs/backup/theme/about. Real empty/error states and user-visible async errors; no default fake traffic.

Additional editing boundaries: `ProfileBuilderDraft` owns a full configuration document and applies only edited leaf fields; its common field widgets and advanced YAML editor retain unsupported fields. Reference updates traverse rules and sub-rules, follow logical rule-provider expressions, and keep proxy targets separate from sub-rule branch names. `ScriptLibraryService` persists a versioned ordered library in settings, disables new/changed code, and feeds `ConfigBuilder` before the profile script and managed overrides. Queued compare-and-set prevents older remote downloads from overwriting a restored library. `ConfigBuilder` initializes the shared Rust library before native script evaluation, including a cold effective-profile preview. `InstalledAppsController` keeps an explicit selection draft, including missing packages; `AndroidInstalledApps` isolates package/permission method channels and bounds icon caching and concurrency. Short-lived editor state stays within its route; saving goes through the existing GetX feature controller or service.

Runtime recovery: failed native config parsing preserves the last applied configuration; Dart restores the last generated file after a rejected hot apply. An unexpected core exit cleans up the owned runtime and retries up to three times with bounded backoff; configuration, permission, TUN and system-proxy failures stop retrying and remain visible with a category. Stopped-core maintenance blocks start/reload during backup selection, confirmation and restore. macOS proxy takeover snapshots/restores previous endpoints, enabled states and bypass domains; partial failures retain ownership so cleanup can be retried. Linux/Windows restoration currently disables task-owned proxy settings and does not snapshot all previous settings.

Testing: config safety and precedence, persistent writes, import/restore failures and traversal, lifecycle latest-intent behavior, transport framing, widget layout at phone and desktop sizes, dark/light themes and controller actions. flutter analyze, flutter test, macOS build. Never start a real VPN during verification. Host previews run DC_PREVIEW=true, only processes started by this task may be terminated by recorded PID.

Shared widgets supplied by foundation (import app/widgets/app_widgets.dart): AppCard({required Widget child, EdgeInsetsGeometry padding = const EdgeInsets.all(20)}); AppPage({required String title, String? subtitle, List<Widget> actions = const [], required Widget child, bool scroll = true}); AppSection({required String title, required Widget child}); AppEmpty({IconData icon = Icons.inbox_outlined, required String title, String? message, Widget? action}); AppSettingsRow({required String title, String? subtitle, IconData? icon, Widget? trailing, VoidCallback? onTap}); AppSearchField({required ValueChanged<String> onChanged, String? hint}); AppPill({required String label, Color? color}); AppDialogs.prompt(BuildContext context,{required String title,String initialValue = '',bool multiline = false,String? hint}) -> Future<String?>; AppDialogs.confirm(BuildContext context,{required String title,required String message}) -> Future<bool>; showAppError(BuildContext context,Object error); formatBytes(num value), formatDuration(Duration value).

Feature page constructors (all no-argument const): ProxiesView, ProfilesView, ConnectionsView, LogsView. FeedView({required bool dns}). Each owns a corresponding GetxController using constructor-injected services; WorkspaceBinding registers them from the composition root. ProxiesController depends on `CoreProxyPort` plus settings, ProfilesController on `CoreProfilePort` plus the profile repository, and ConnectionsController/LogsController on `CoreActivityPort`. Views live in app/pages/{proxies,profiles,connections,logs}. All display text goes through `.tr` keys or shared translations; page implementer may add configs/localization/feature_translations.dart map and tell parent to merge it.
